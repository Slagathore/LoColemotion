## Active - SDK2 discovery and Studio completion, 2026-11-01

Start with the [current roadmap](SDK_PRODUCT_AND_ADAPTATION_ROADMAP.md).
It owns the next work order: actual creature/controller populations, rigorous
fresh checks of a diverse shortlist, and useful SDK/Studio behavior. Read this
page for claim boundaries. Search the
[dated master ledger](ENGINE_NEUTRAL_LOCOMOTION_SDK_BOOTSTRAP_HISTORY_2026-11-01.md)
for a specific historical identity; its dated "active" and "next" passages are
historical instructions.

| --- | --- |
| SDK1 package | [20/20 bounded milestones](../sdk/release/sdk1_package_acceptance_closure_v1.json); full-program progress remains 19/25 with six deferred gates |

SDK1 package qualification does not grant permission to redistribute the
watermarked native candidates or claim unrestricted morphology support.
Read the [support matrix](../sdk/release/quadruped_support_matrix.json) and
[release contract](../sdk/release/quadruped_release_contract.json) before
publishing any stronger claim.

The population v1 canary failure remains a
[negative record](../sdk/discovery/population_discovery_native_failure_v1.json);
it opened zero population worlds. The latest full-capture run used a clean
pushed prospective freeze, fresh worlds, complete scalar decision replay and
native-stream checks. It neither trained a provider nor opened evaluation groups.
A future condition-known comparison would measure the value of choice; it
would not by itself satisfy Tier 2.

Earlier [native contextual-memory work](../sdk/discovery/gpu_contextual_influence_closure_v1.json)
verified learned influence and feedback mechanics in a finite development setting,
but memory missed its benefit criterion in every group. Those results remain;
the current shortlist is an untrained search and does not replace them.

The [portable lineage](SDK_PORTABLE_BALANCED_WAVE_SUCCESSOR_BOOTSTRAP.md)
points to the active implementation and evidence. The
[research program](LOCOMOTION_GROUND_UP_RESEARCH_PROGRAM.md) defines evidence
and audit economy; the [architecture](LOCOMOTION_ARCHITECTURE.md) defines
runtime ownership. New attempts preserve consumed identities and add declarations
to shared machinery wherever the contract is unchanged.
